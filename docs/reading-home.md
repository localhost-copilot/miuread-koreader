# 阅读桌面

本 fork 的桌面沿用 MiuRead 6.0.0 的书架、下载、同步和阅读流程，重排首页、书架、书城、书籍操作和工具页。

## 布局和入口

- 顶部显示名称、日期、时间、网络图标与电量。点名称查看账号，点网络或电量打开控制中心；Wi-Fi 名称在控制中心显示。
- 继续阅读卡片显示最近书籍、来源、作者、进度和阅读时间。点卡片或“继续阅读”沿用原来的打开流程。
- 阅读摘要优先显示已启用且可用的微信统计，否则显示本机统计，并注明来源。微信与本机时长可能重叠，因此不相加。点摘要可分别查看两种统计；两种统计都关闭时隐藏摘要。
- “我的书架 ▾”打开来源选择，右侧保留排序、书架搜索与全部书籍入口。下方保留“书架 / 本机 / 最近”三个视图。
- 竖屏每页三列两行，横屏每页六列一行，始终六本。固定容量使切换方向时不会漏书；末页沿用完整页的卡片尺寸。可用箭头或原有滑动手势翻页。
- 底栏固定为“首页 / 书架 / 书城 / 工具”。“首页”回到首页书架视图，“书架”打开全部书籍列表，“书城”打开微信读书书城，“工具”打开工具页。当前位置以实心图标、粗体和下划线标明；从书城进入书籍操作时保留“书城”选中态，其他书籍操作页选中“书架”。

## 书架、书籍操作与工具

- 书架默认每页六行，显示封面、书名、作者、来源与状态；右上可切换封面视图，保持当前页。来源、排序、搜索与“全部 / 阅读中 / 已读完”沿用原有筛选逻辑；更多菜单保留未读、本机已有、异常等条件。空结果仍保留筛选和导航，方便改回条件。
- 从书架点书进入书籍操作页。阅读按钮在打开正文前关闭操作页，其余动作沿用现有对话框；关闭对话框仍能回到操作页，返回书架保留原页码。动作超过六项可翻页，全部下载版本和其他操作保持可达。
- 从微信书架移除的动作单独放在底部，仍使用原有确认及授权流程，保留本机文件。未启用觅阅桌面时沿用旧操作面板。
- 工具页显示单行 Wi-Fi 名称、连接状态及亮度、暖光控制。点击 Wi-Fi 打开原有网络设置；顶部设备控制进入原有控制中心。同步按钮沿用同步流程，长按可查看状态；下载、历史、文件管理、扩展及两套设置保留原入口。“更多工具”保留休眠、刷新和用户自定义快捷操作。
- 固定底栏切换时关闭旧页面与对话框。书架筛选和书籍操作弹窗保留其父页面；后台首页在子页面可见时暂停绘制，避免覆盖当前页。
- 从正文返回时，由仍存活的桌面实例恢复点击回调和后台任务。阅读实例随 ReaderUI 销毁，不能继续持有首页的延迟刷新，否则可能在首页恢复数秒后崩溃。

书名、作者和状态栏文本使用有宽度限制的控件。时钟、电量和统计变化只更新对应区域；书架分页与单本进度更新继续使用原有图层缓存。

## 书城

书城首页提供搜索框、推荐卡片、排行榜、分类浏览和微信书架入口，打开首页本身不请求账号接口。分类、子分类和榜单采用整页列表，长名称截断，每页六项；左上返回，右上刷新。

推荐、榜单、分类和搜索结果共用六本一页的列表/封面布局，列表显示作者及原有推荐或榜单状态。列表与封面切换保留页码，跨服务端批次保留显示方式。“上一批 / 下一批”沿用服务端游标，底部页码仅切换当前批次中的六本书。空结果仍可搜索、返回或切换底栏。书籍操作返回已缓存的结果，不重新请求列表；阅读、下载、相似推荐、章节扩展、详情、读完标记和书架管理均保留。移除操作单独显示，沿用原有确认、授权与不明确结果恢复流程。

## 实现边界

`miuread/home_layout.lua` 共享首页分页容量与屏幕几何。`main.lua` 提供导航、筛选与业务回调；`home_view.lua`、`full_shelf_view.lua`、`bookstore_view.lua`、`book_actions_view.lua` 和 `tools_view.lua` 负责各页面控件。`bookstore.lua` 保留书城网络、缓存及书架写入控制。`desktop_ui.lua` 共享状态栏、底栏与子页面生命周期；`control_slider.lua` 供工具页和原控制中心共用。子页面每分钟仅更新可见状态栏的时钟和电量，关闭后取消计时任务。

嵌套设置及下载对话框继续使用现有界面。未启用觅阅桌面时保留原有书城列表。本轮不修改阅读位置、下载恢复、书架管理协议或固件。

## 刷新与性能

选择已经选中的书架视图、或滑动超出书籍操作页的首尾边界时，不重建控件和刷新屏幕。切换目的页或打开正文时，由目的页面负责刷新，避免关闭的隐藏页面再次请求整屏闪刷；显式返回仍保留清屏刷新。

书架与书城结果的新封面只替换对应图片控件，使用图片矩形的非闪烁 `ui` 刷新；标题、点击区域、分页和底栏不重建。没有变化的图片不刷新，被其他页面或弹窗遮挡时只更新控件，待正常返回绘制。旧书架组件继续使用原有刷新回调。

底栏导航在同一帧内关闭旧页并显示目的页，避免中间露出首页后触发原生 `partial` 刷新及其累计清屏计数。目的页内容与底栏选中态使用非闪烁 `ui` 波形；页面内容大幅变化时仍需更新整个视口。列表重建仅更新状态栏与底栏之间的内容区域；旋转和尺寸变化保留清屏刷新。离开首页会取消尚未执行的书架清屏任务，延迟任务也检查当前顶层页面，避免切换后突然闪屏。

打开正文的性能样本在首次绘制后采集，不再把随后固定 1.2 秒的后台保护等待计入首屏耗时。保护等待和慢操作检测阈值保持原值，真实慢首屏仍会记录。轻量模式沿用上游实现，可在性能设置中切换；它调整后台维护调度，不改变布局、封面质量或阅读功能。

从文件管理器打开正文时，CoverBrowser 的关闭回调会延迟执行两次完整内存回收，随后 DocumentRegistry 打开文档前又执行两次。`reader_open_gc.lua` 在原生打开协程确已排队时，合并本次关闭产生的那一组重复回收；DocumentRegistry 在分配文档前的两次回收保留。封面插件关闭工作、数据库清理与其他任务照常执行。通过函数来源和定义范围识别本次回调；缺少 CoverBrowser、原生方法被包装或进入书籍元数据恢复确认时保留原流程，不修改 KOReader 核心文件。

保留上游版本号、Schema、账号凭据和同步策略。本修改未增加后台时钟服务、常亮或整机启动服务。更新上游插件可能覆盖 fork 文件；安装前备份插件和设置，不要在运行中的 KOReader 内替换文件。

上传工作器明确成功时，诊断字段与上传结果在同一次保存中提交；不明确或失败的响应仍先保存恢复所需的诊断。进度请求被接收后，待确认位置快照和“已提交”状态也一次写入，之后才通知调用方并进入独立的云端验证阶段。这里没有引入延迟保存：请求发出前的快照、提交后的快照和云端验证状态仍各自持久化。

打开回收回归使用受控任务调度，检查文档分配前仍完成原生回收，以及恢复确认、此前的菜单关闭、其他任务和不兼容实现仍保留原行为。

## 回退

部署前备份整个 `plugins/miuread.koplugin`、`settings.reader.lua` 与 `settings/miuread.lua`，备份应放在插件目录之外。设置备份可能包含登录凭据，不应提交到仓库。

此次设备部署的备份为 `koreader/local-backups/pre-reading-home-20261026/`。退出 KOReader 后，用其中的 `main.lua` 和 `home_view.lua` 恢复对应插件文件，并移除新增的 `miuread/home_layout.lua`，再启动 KOReader。仅回退界面无需恢复整个设置备份，避免覆盖随后产生的阅读进度。

后续三页与底栏选中态的部署备份为 `koreader/local-backups/pre-desktop-pages-20261026/`。仅回退这一轮时，退出 KOReader，恢复 `files/` 中保留的四个原文件到插件内对应路径，移除新增的 `miuread/{desktop_ui,book_actions_view,tools_view,control_slider}.lua` 和四个 `resources/icons/miuread/*-selected.svg`，再启动 KOReader。备份的 `before.tar` 包含完整部署前插件及私人设置；只回退界面时无需恢复设置。

书城与进度写盘合并的备份为 `koreader/local-backups/pre-bookstore-progress-20261026/`。仅回退这两项时，在 KOReader 停止运行后恢复 `files/` 中的五个原文件，并移除新增的 `miuread/bookstore_view.lua`。`before.tar.gz` 含部署前完整插件与私人设置；正常回退不恢复旧设置，以免覆盖新阅读进度。

封面与底栏局部刷新版本的备份为 `koreader/local-backups/pre-partial-refresh-20261026/`。仅回退这一项时，在 KOReader 停止运行后恢复 `files/` 中四个原文件；无需恢复私人设置。
